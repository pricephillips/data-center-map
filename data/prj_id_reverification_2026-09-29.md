# Project-id citations re-verified (2026-09-29)

The source renumbered its project ids on 2026-09-17 and again on 2026-09-22 (and partly on 2026-05-01, 05-21 and 07-02). A `prj_` id below 1000 written before a renumbering can now point at a different project. This report checks every such citation in the repo's reports, worklists and coding files against `data/pipeline_intel_id_timeline.csv`: the id is resolved to the project it named on the day the line was written (`git blame`), then to that project's id today. Lines that are themselves an old-to-new id crosswalk (they also cite a `prj_1xxx` id) are skipped.

97 distinct stale citations in 11 dated reports and docs; 0 of them name an id the history cannot resolve on that day.

## Scope and outcome

- **Hand files the key map maintains** (`proposals_manual_overlay.csv`, `project_decision_dates.csv`, `project_links_manual.csv`, `project_duplicates.csv`, `negative_audit_codings.csv`): rewritten by `project_key_map.py` on every renumbering; none stale.
- **Landmark worklists** `decision_date_worklist.csv` and `announce_date_worklist.csv` were last written 2026-09-02 and 09-03, before the renumberings, and 59 of their id citations had moved. Regenerated by `landmark_model.py` in this change.
- **Regenerated every run** (`link_disagreement_worklist.csv`; `site_screen_history.csv`, whose rows are dated snapshots): current as written.
- **Frozen spike outputs** (`splink_spike_scores.csv`, `splink_spike_eval.csv`, 2026-07-27): their ids are 2026-07-27 ids. Do not join them to today's tables without this crosswalk.
- **Dated reports and docs** (below) are records of their day and are left as written. Read each listed id as the project in the table, which today carries the id in the fourth column. "Line names it" means the same line also names the project, so a reader is not misled.
